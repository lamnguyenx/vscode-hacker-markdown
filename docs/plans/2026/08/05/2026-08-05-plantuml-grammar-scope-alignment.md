# Plan: Align PlantUML fence scopes with the Eink 60Hz theme (colors & font styles)

**Date:** 2026-08-05
**Status:** DONE — implemented & verified offline with the real tokenizer
(`npm run compile` passes; `vscode-textmate` 9.3.2 + `vscode-oniguruma` tokenization of
the shipped grammar themed exactly as VS Code themes it, checked under the
theme alone **and** with the `make mate` user-`textMateRules` layer).
**Source:** `_refs/vscode-eink-60hz-theme` (Eink 60Hz theme, `themes/dark_plus.json` +
`text-mate-rules/dark_plus_text.json`) and `_refs/vscode-textmate` (v9.3.2 reference).
**Files edited:** `syntaxes/plantuml.yaml-tmLanguage`, `syntaxes/plantuml.tmLanguage.json`
(regenerated by `scripts/build-syntax.cjs`), `docs/important/{architecture,how-to-test,quirks}.md`

## Problem

The Eink 60Hz theme differentiates tokens by **font weight/style**: bold for
keywords/functions, italic for strings/comments/params, bold-italic for
types/classes, plus full colors. Fenced `plantuml`/`puml`/`uml` blocks in
Markdown (tokenized by the vendored `source.wsd` grammar, injected via
`syntaxes/codeblock.json` as `meta.embedded.block.plantuml`) did not follow
that design:

1. **`@startuml`/`@enduml` (and link arrows `->`) rendered purple `#C586C0`** —
   the grammar tagged them `keyword.control.*`, which the theme's
   "Control flow / Special keywords" rule paints purple, not keyword blue.
2. **Identifiers were flat cyan with no weight** — the grammar emits
   `support.variable.*` for every plain word (participant/class/member names,
   message targets), and the theme styles that family as plain
   `#9CDCFE` (variables are "normal" by design). Mostly-unstyled was the
   dominant look of a diagram body.
3. **Class member signatures rendered as italic strings** — the grammar's
   "other fields/function" catch-all scoped `+log(String msg) : int` as
   `string.quoted.double.class.other.*`, so signatures showed italic brown
   instead of looking like declarations.

## Why this approach (align scopes to the theme, not the theme to us)

The theme lives in a separate, read-only reference repo (`_refs/vscode-eink-60hz-theme`).
Its design intent is fixed (the 5-style semantic map in the theme README). The
lever in **this** repo is the grammar: TextMate scope names are internal to
token theming, so we re-scope plantuml tokens onto the standard scope families
the theme already styles the way the user wants — no theme edits, and the
behavior degrades gracefully under any other theme (each new scope has a
generic family fallback).

## Design

Three deletion-independent scope renames in `syntaxes/plantuml.yaml-tmLanguage`
(the YAML is the source of truth; `scripts/build-syntax.cjs` regenerates
`plantuml.tmLanguage.json`, which keeps the `.json` suffix vscode-textmate requires):

| # | Edit | Old scope | New scope |
|---|------|-----------|-----------|
| A | `@start\w+` / `@end\w+` captures and `->` link-marker capture | `keyword.control.diagram.*`, `keyword.control.note.*` | `keyword.other.diagram.*`, `keyword.other.link.*` |
| B | class "other fields/function" capture 4 | `string.quoted.double.class.other.*` | `entity.name.function.class.other.*` |
| C | all 20 `support.variable*` captures (catch-all + class/noteof/noteas/actor/sequence/object/definitions variants) | `support.variable*` | `variable.other.enummember*` |

Why these specific targets, per the Eink theme's rules:

- **A** — keeps the diagram delimiters in the `keyword` family so they render
  **bold blue `#569cd6`** (the theme's `keyword`/`keyword.control` rules), instead
  of the `keyword.control`-purple `#C586C0`.
- **B** — `entity.name.function*` is the theme's "function declaration" family
  (**bold** `#DCDCAA` theme / `#a5a574` with `make mate`), i.e. a declaration look.
- **C** — `variable.other.enummember*` is the theme's "Constants and enums"
  family: the theme bolds it while its color still falls back to the `variable`
  rule (`#9CDCFE` cyan). Identifiers keep the variable palette but gain weight —
  the names stand out against the flat body. (Fallback under other themes:
  `variable.other.enummember` resolves through the generic `variable` family.)

## Verification (offline, faithful to the editor)

The final editor style is computed by `vscode-textmate`'s `Theme.match`
(vs-code feeds it `colorTheme.tokenColors` = default rule + theme `tokenColors` +
user `editor.tokenColorCustomizations.textMateRules` + type defaults + the
precomputed `tokenColorMap`; see `colorThemeData.ts#tokenColors`, `#getTokenColorIndex`).
So the harness (`exp/themecheck/tokenize.cjs` + a stub of
`EncodedTokenAttributes` bit offsets from `_refs/vscode-textmate/src/encodedTokenAttributes.ts`)
tokenizes the **shipped `plantuml.tmLanguage.json`** with `vscode-textmate@9.3.2`
and resolves `metadata → color + fontStyle` against both:
1. the Eink theme alone, and
2. the Eink theme + the `make mate` custom rules.

Sample result (representative diagram; identical tone under both layers):

| Token | Before | After |
|---|---|---|
| `@startuml` / `@enduml` | `#C586C0` bold (purple) | `#569cd6` bold |
| `->` / `-->` | `#C586C0` bold | `#569cd6` bold |
| `A`, `Logger`, `name`, `success` (identifiers) | `#9cdcfe` plain | `#9cdcfe` **bold** |
| `+log(String msg) : int` | `#b07050`/`#925a3f` italic | `#DCDCAA`/`#a5a574` **bold** |
| `String ` (class type) | `#4EC9B0`/`#1b6355` bold italic | unchanged |
| `' comment` / `"Alice"` | italic green / brown | unchanged |

Gotcha handled during investigation: the released npm `vscode-textmate` bit
layout differs from the `_refs` source's JSDoc header — the real
`EncodedTokenAttributes` constants (`FOREGROUND_OFFSET=15`, `BACKGROUND_OFFSET=24`)
came from the actual `const enum` in `_refs/vscode-textmate/src/encodedTokenAttributes.ts`,
not the stale `F=4/f=9` comment block.

## Testing / re-running

- `npm run compile` regenerates the grammar + bundles (exit 0).
- Offline token check: `node exp/themecheck/tokenize.cjs` (theme+mate) /
  `node exp/themecheck/tokenize_theme_only.cjs` (theme alone).
- Live dev-host check follows `how-to-test.md` §3f: relaunch the host,
  then **close and reopen** the fixture document (open editors cache
  tokenization; `Reload Window` alone is not enough), and read `textmate scopes`
  for a fence body: it now shows `keyword.other.diagram.*`,
  `variable.other.enummember.*`, `entity.name.function.class.other.*` on top
  of `meta.embedded.block.plantuml` / `source.wsd`.

## Residual / by design

- Note/message bodies (`meta.comment.*`) remain plain white; `===`/`--` dividers
  plain; `"separator"` inside a divider stays `string.quoted.double.sequence.divider`
  (italic) — untouched.
- Scope renames apply to standalone `.puml`/`.wsd` files too (same `source.wsd`
  grammar) — consistent with the theme everywhere.
- Other themes: every new scope falls back to a generic family
  (`keyword.other`, `variable.other.enummember`, `entity.name.function`); colors
  will be whatever that theme assigns — no orphaned/invisible tokens.
